# 耗材色域与缓存

在「耗材管理」中打开「色域覆盖」或「求解缓存」。两个页面共享耗材组合、层高、
固定层数或动态层数范围。转换页的「查看色域」「管理缓存」会带入当前组合；
之后在工作台选择的组合不会修改转换设置。

## 色域覆盖

- 覆盖率统计可打印颜色触达的 sRGB 色彩单元，默认使用边长 5 ΔE 的 Lab 单元。
  它衡量颜色范围，不能单独衡量配色精度。
- 匹配误差以均匀分布的 sRGB 目标色为参考，在各目标色的八个最近 Lab 邻居中
  计算最小 ΔE00，再按灰黑白、暗色、肤色、鲜艳色等组取平均。这是近邻估计，
  不保证是全部候选中的全局最小 ΔE00。
- 「候选完整」只表示保留了全部配方的候选颜色。分桶穷举缓存和未完整枚举的
  采样缓存显示「候选近似」。固定层数包含缓存中单独保存的纯色叠层。
- 「各耗材的贡献」逐一移除耗材，在同一固定层数与 1M 候选预算下重新计算。
  动态模式使用最大层数进行此项比较；它与动态补位目录的总覆盖率不是同一个指标。
- 动态模式还显示不同有效层数上限的累计覆盖率。冷缓存计算会先保存逐层候选，
  再构建合并目录，后续转换可复用这些文件。

## 求解缓存

固定层数沿用穷举和智能缓存操作。动态模式的「预构建」保存逐层候选和合并目录；
逐层候选位于求解缓存下的 `dynamic-layer-runtimes` 子目录，固定层数查找不会读取它。
已有手动智能缓存可以被动态模式复用，但不会被「删除预构建缓存」删除。
缓存概览分别返回全部可复用的 `saved_layer_counts` 和可删除的
`prepared_layer_counts`；只有手动缓存时不显示预构建删除操作。

删除会移除当前组合与层数范围对应的合并目录数据和预构建逐层候选。没有合并目录时
也能删除已有逐层数据。小型目录注册记录与锁文件保留，以便并发构建继续使用相同的
缓存标识；下一次转换可按需重建。注册记录本身不表示缓存已就绪。

## API

以下端点均为 `POST /api/extractor/<path>`，使用现有的本地应用来源检查和表单字段。

| path | 用途 |
| --- | --- |
| `material-gamut/coverage` | 覆盖率、误差估计、亮度范围与散点图 |
| `material-gamut/contributions` | 逐个移除耗材的贡献比较 |
| `material-cache/overview` | 仅读取元数据的缓存状态 |
| `material-dynamic-cache/prepare` | 动态缓存预构建 |
| `material-dynamic-cache/delete` | 删除动态预构建数据 |

公共字段为 `material_directory_names`（JSON 字符串数组）、`layer_mode`、
`layer_height_mm`、`substrate`。固定模式需要 `layer_count`；动态模式需要
`min_layer_count`、`max_layer_count` 和属于所选耗材的 `backing_material_directory_name`。
层数范围为 5–10。参数错误返回 422；动态求解器暂时不可用时沿用统一的 503 错误结构。
覆盖、贡献、预构建和删除共享缓存构建的并发限制；状态查询不占用构建名额。
构建名额等待超过 30 秒时返回可重试的 503，`stage` 为 `material_compute_queue`，
而不会无限等待。
