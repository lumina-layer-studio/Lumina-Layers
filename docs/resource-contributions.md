# 社区账号、资源收藏与投稿

Studio 的耗材档案和 LUT 使用耗材服务器现有账号、投稿记录与审核流程。客户端负责选择本地资源、整理文件和填写资料，服务器负责身份、审核和发布。

## 用户入口

- 耗材库／LUT 库：打开资源详情 → **贡献到公共库**。
- 梯度卡提取：保存档案后，可直接贡献。
- LUT 提取：确认调色板后，**保存到本地并贡献**；先保存完整 LUT，再打开同一个投稿表单。
- 两个本地库工具栏均有 **我的投稿**，合并显示同一账号的耗材与 LUT 投稿、状态及审核意见。待审记录可撤回审核，再修改或重新提交；已公开记录可提交资料修订，也可进入现有网页查看。

首次点击“连接社区账号”后，在耗材库网页登录，核对十位连接码并允许连接。客户端自动刷新连接结果。网页优先使用邮箱验证码，新邮箱验证后直接创建普通社区账号；密码、邀请码和 GitHub 登录继续使用原有流程。已有但尚未验证邮箱的账号必须先用原方式登录，再验证一次邮箱，保持原用户编号、投稿、收藏与权限。常规设置只保留一行账号入口，投稿和互动都复用同一个连接弹窗。

贡献必须主动确认使用许可、来源和当前投稿账号。新增原创数据采用 [Lumina 数据协议 1.0](../DATA-LICENSE.md)：允许接单打印，禁止售卖数据、收费分发或搭收费资源库；已有许可的版本保留原条款。自动贡献默认关闭；在“我的投稿”单独确认后，今后的新校准保存才会入队。旧 CC BY 4.0 自动贡献授权不能替代新协议确认，旧快照保留原许可，重新开启不自动恢复旧任务。浏览、下载、导入和历史文件不触发上传。连接码 10 分钟有效、只能确认一次。具备系统加密存储的 Electron 桌面端会安全记住设备，重启后自动连接；浏览器和缺少安全存储的源码环境使用最长 12 小时的会话连接，重启后重新连接。界面明确区分两种状态。

“使用许可”表示这份资源已有的声明，没有声明就显示“未标注”；下方“投稿数据协议说明”是一般说明，不替旧数据授予新许可。再次投稿时从已验证安装记录保留原许可，即使普通 `.npy` 本身不包含元数据；待补资料快照与最终 ZIP 使用相同规则。

桌面访问凭据 1 小时有效，续期凭据每次轮换，90 天不活跃或授权满 365 天需重新连接。轮换保留 120 秒重试窗口，处理响应丢失。长期凭据由 Electron 主进程通过 `safeStorage` 加密保存到该工作区的 `userData/community-accounts.enc`，不同服务地址分别保存；前端、设置文件、共享材料目录和分享卡不保存凭据。后端通过只监听回环地址、独立随机认证的临时通道访问加密存储。系统存储不可用时不阻碍本地创作，账号显示为会话连接。

“管理邮箱与设备”进入耗材库网页 `/#/account`，可验证已有账号邮箱、更换邮箱、查看和逐台撤销设备。更换邮箱要核对旧、新两份验证码，保持用户编号、投稿、收藏和角色；成功后更新当前网页会话，并撤销其他网页与 Studio 连接。旧邮箱丢失时，由维护者核验原身份后使用受限管理员恢复入口，同时验证新邮箱，不创建替代账号或按昵称合并。网页退出登录与撤销 Studio 设备是不同操作；Studio 断开连接会清除本机保存并撤销当前设备。断网时先退出本机连接，明确提示服务器授权尚待撤销。

## 点赞、收藏和下载

云端耗材／LUT 卡片公开显示点赞、收藏和下载人数，未登录也能查看。点赞与收藏归属账号；图像转换中的两类选择器共用相同记录，任一入口取消后另一入口立即更新，转换时已选的材料保持不变。其他窗口的修改在回到窗口后刷新本人记录。未下载的账号收藏从云端选择后按需下载，不自动装入本机。

纯本地耗材仍可设为“本机常用”，旧的浏览器收藏也保留在那里。公开资源通过同步 ID、修订 ID 和实际内容校验关联；同名档案不会混用收藏。公开历史版本沿用资源身份，升级不另建收藏。退出或切换账号清空客户端的个人状态；公共统计重新读取。个人记录不写浏览器持久化存储。

“下载人数”指成功下载的不同账号数，同一账号重复下载或更新版本只计一人。Studio 完成包校验与安装后记录；服务网页完整下载响应发送后记录，范围请求不记。匿名下载、离线添加及接入前历史下载不补算；安装成功但账号服务不可达时保留文件并提示记录未同步。收藏人数公开，但不公开收藏者名单或邮箱。

互动端点由现有账号主站提供：

- `GET /resources/{materials|luts}/activity?resource_id=...`：每次最多 100 项，返回可见公开版本的真实总数及当前账号状态。
- `GET /me/resources/{materials|luts}/activity`：本人点赞／收藏／下载记录，分页最多 500 项。
- `PUT /me/resources/{materials|luts}/activity`：绝对状态更新，校验当前账号、CSRF、公开资源身份与内容；可清除已下架资源的本人点赞和收藏。

Studio 经本机后端代理，只请求当前可见资源的统计，使用 30 秒、最多 1,000 项的内存缓存。本人筛选先取得轻量 ID 集合，再筛选全目录；不预下载资源包。统计未知时显示“—”，不会把接口不可用误显示为零。

资源分发地址与互动服务独立。GitHub 目录、实时目录和整包加入本地的资源保留相同的资源 ID、修订 ID 和内容校验；投稿、点赞、收藏及本人筛选使用同一个社区账号，无须 GitHub 账号。源码默认匿名读取 GitHub 的统计快照，统计附带生成时间；官方实时目录查询社区实时总数。离线包目录目前没有互动栏，添加到本地后可在关联资源的选择器中使用账号收藏。静态读取与 Registry 本地导出已经实现，首份 GitHub 快照尚未发布，详见[资源分发](resource-distribution.md)。

社区服务无法连接且没有此前成功的统计时，数量显示“—”；服务未识别该资源或内容不匹配时同样显示“—”。只有成功取得真实零值才显示 0。当前会话已读到的数据在刷新失败时会保留，不能将其视为离线实时统计。

## 数据与身份

耗材包只包含 `material.json`、`stage_A_parameters.json` 和包清单。保留拟合参数、校准几何、质量摘要与实际梯度预览，去掉原始照片、来源路径、逐次验证记录和本地使用记录。原始档案不被修改。

LUT 保留 `.npy`、键控 `.json`、`.npz`、`.msgpack` 文件原始字节。模式、层高、配方与通道顺序从解析器读取；填写公开资料不会改写算法数据。五色／八色双板共用一组通道，`slot` 从 0 开始。

表单带入已有品牌、材质和包装资料。LUT 按实际通道填写品牌、材质、颜色，可选本地耗材档案带入；有同步 ID 时同时保存耗材 ID 和修订 ID，手动改动商品信息后取消关联。购买链接按通道填写，地区使用 `CN`／`INTL`／`ALL`。本次表单每卷料提供一个购买链接，目录仍兼容历史多链接数据。

公开署名来自连接的服务器账号。客户端确认时绑定账号 ID，另一个窗口切换账号后，旧确认不会被当成新账号的授权。LUT 服务端覆盖客户端自报的投稿者字段；耗材沿用现有校准来源记录。账号身份表示可追溯的投稿者，不自动授予品牌官方或赞助身份。

来源声明独立于投稿身份：`display.attribution.relationship` 为 `original`、`adapted` 或 `redistributed`。修改或代传还需 `original_author`、`rights_basis`，以及公开 `source_url` 或确切原资源引用 `source={kind,resource_id,revision_id,content_hash}`。已安装资源的引用由本机后端补入，客户端不能替换；原作者和授权说明是待审核声明，不是原创认证。相同 LUT 内容对应多个公开资源时要求填写实际来源，不任意选择一个作者。旧条目没有来源声明时保持空缺。

投稿资源 ID 绑定账号与本地资源键，修订 ID 绑定数据和确认的公开资料。同一次投稿失败后，重试先查现有记录；已收到的 LUT 不重复上传，已收到的耗材草稿接着提交审核。修改资料后形成新的修订；审核中与已公开内容仍沿用服务器原有权限。

## 新校准自动贡献

“我的投稿”的折叠设置中，已连接且邮箱已验证的用户可单独同意 `public-calibration-v1`，开启今后的新校准贡献。默认关闭，普通设置文件不会携带该同意。服务端连接状态只额外返回 `email_verified`，不把邮箱地址暴露给资源目录。

梯度卡档案保存成功、最终提取 LUT 加入本地库后，API 冻结技术数据和公开资料。保存动作不请求远端。队列在后台上传，断网按最长一小时的退避重试；每次重试先查现有服务端投稿回执。原文件修改或移除、提取会话关闭、程序重启不影响快照。品牌／材质或 LUT 通道资料不完整、来源需要确认时留在“本机待提交”，复用原投稿表单补齐冻结版本后继续。

修改已有档案时，只有保存前内容确实匹配本工作区、同一账号已记录的原创快照，才沿用原创来源；名称一致不能替代内容核对。公共来源及不明确的历史数据需要人工确认。原始照片、导入动作、下载动作和纯元数据修改没有入队钩子。

持久数据库在共享耗材根 `_sync/contributions/queue.sqlite3`，按工作区、服务地址和账号隔离；整个共享根合计最多 100 个未完成快照、512 MiB。工作区由 `LUMINA_CONTRIBUTION_WORKSPACE` 指定，未指定时使用 `LUMINA_SETTINGS_PATH` 的目录，再退回耗材根；Electron 传入其 `userData`。发行侧需要保证附加实例有不同工作区，版本切换继续使用同一持久位置。

后台进程通过跨进程文件锁串行处理，退出时等在途请求存回执；崩溃后重新核对服务器。关闭自动贡献、断开账号会暂停未开始的队列，再次开启不自动恢复旧任务。暂停项目可逐项恢复；未发送的可移出队列，释放快照。服务器已接收的记录保留轻量回执并释放快照，后续审核以服务器为准。旧版遇到未知队列结构停止处理，不改写它。

“我的投稿”支持待审撤回、重新提交和资料修订。耗材撤回后回到草稿，LUT 为 `withdrawn`；已公开记录不能用撤回审核按钮下架。修改取回仅本人可下载的服务器分发包，逐文件校验后保留技术字节，为同一资源生成新修订；已公开旧版在审核期间继续可用。不同会话的新校准可明确选择“更新哪份投稿”，仍需核对同一组耗材及通道；系统不按近似名称自动关联。LUT 各槽位继续通过材料 ID／修订关联实际档案。来源争议与资源反馈见下文。

目录的“来源设置”与设置页共用入口，支持默认线路、GitHub 和兼容静态镜像。偏好保存在 `LUMINA_SETTINGS_PATH` 同目录的 `resource-sources.json`，按工作区独立，不写进通用设置导出、分享卡或账号凭据。两类目录一起切换，保留本地安装和搜索筛选；失效请求不能覆盖新来源，回到其他窗口会重读配置。静态目录只读公开频道、不发送私有令牌、不自动回退到官方账号主站。检查线路只取轻量目录，不下载数据包；缓存显示实际核对时间。

## 配置与升级

| 用途 | 默认地址 |
| --- | --- |
| 源码默认公开目录 | `https://raw.githubusercontent.com/lumina-layer-studio/Lumina-materials/master/public/v1` |
| 打包版实时目录 | `https://materials.luminastudio.com.cn/api/material-registry/v1` |
| 账号与投稿主站 | `https://dan5.shmx.top/api/material-registry/v1` |

`LUMINA_CONTRIBUTION_REGISTRY_URL` 覆盖账号与互动主站；显式空值禁用这些功能。只允许 HTTPS，回环开发地址可用 HTTP。不继承读取令牌，不向镜像回退，不跟随投稿重定向。

主站需要本次 Registry 更新：数据库自动迁移到 v19，邮箱校验、验证码限流、临时连接、设备授权、互动和私人反馈记录均存放在原 `LUMINA_REGISTRY_DATA_DIR/application.sqlite3`，用户仍使用原来的表。服务新增同目录的 `auth-secret.key`，应与数据库一并备份；它用于验证码校验与设备轮换，不进入数据仓库或公开快照。旧服务器尚未支持设备授权时，客户端保留原会话连接。

连接路由为 `/auth/studio/start`、`approve`、`status`、`disconnect`，新增 `device`、`refresh`、`devices`；邮箱路由为 `/auth/email/config`、`start`、`verify`，更换邮箱为 `change/start` 与 `change/verify`。设备授权只允许本人点赞、收藏、下载记录与耗材／LUT 的创建、提交、查询、待审撤回和本人分发包下载，不继承审核或管理权限。

服务器配置 SMTP 后开启邮箱入口：`LUMINA_REGISTRY_SMTP_HOST`、`LUMINA_REGISTRY_SMTP_FROM`、可选 `LUMINA_REGISTRY_SMTP_PORT`、`LUMINA_REGISTRY_SMTP_SECURITY`（默认 `starttls`，支持 `ssl`）及成对的 `LUMINA_REGISTRY_SMTP_USERNAME` / `LUMINA_REGISTRY_SMTP_PASSWORD`。未配置邮件时保留原登录方式。验证码为 6 位、10 分钟有效、最多 5 次尝试；60 秒重发，每邮箱每小时 5 次、每 IP 每小时 20 次、全局每小时 200 次。限流持久化，重启不重置。

耗材资料归一、审核摘要、发布包与目录投影共用字段集合，保留系列、色号、货号、地区名称、最多八条地区购买链接、许可和梯度预览。升级前的主站返回明确的升级提示。本地验收版本将投稿指向 `127.0.0.1:8018`；线上服务尚未部署。

邮箱／GitHub 已配置后正常开放注册，无需额外开启。`LUMINA_REGISTRY_PUBLIC_REGISTRATION_ENABLED` 默认 `true`，只在运维明确设置为 `false` 时暂停公开注册。暂停时已有账号仍可登录、验证邮箱和绑定 GitHub，受邀注册继续有效。客户端按 `/auth/email/config` 的 `registration_open` 显示登录或登录／注册文案；暂停时未知邮箱不会实际发信，响应不泄露邮箱是否已注册。正在验证的流程也在创建账号前重新检查开关。

## 当前边界

本地已实现用户主动投稿、来源声明、自动贡献与持久队列、邮箱验证码登录、既有账号验证、长期设备授权、账号互动和状态查询。已补齐来源切换、邮箱更换与管理员人工恢复、待审撤回／重新提交、资料修订及显式跨会话校准关联，以及下述资源反馈闭环。GitHub 发布器和定时任务模板已通过本地验收，尚未启用；正式云权益联动仍未完成。按用户 2026-11-16 的安排，云端数据整理与首次公开发布后置。提交仍进入服务器现有待审核流程，审核通过后进入公开目录。

正式服务尚未部署，真实发信域名配置、QQ／163 邮箱送达和实际 macOS／Windows 打包程序的系统凭据存储仍需上线前验收。自动化覆盖加密存储接口、进程重启、轮换、撤销与失败恢复，不把加密替身测试当作操作系统验收。

本地验收主界面端口 4187、Studio API 8017、Registry 8018；早期界面快照使用 174 份耗材和 136 份 LUT，不代表当前正式公开数据。2026-11-18 收尾冻结的完整离线资源为 662 份耗材和 99 个 LUT，包含明确署名的六朔厂商供稿。真实邮件已投递用户指定 Gmail；服务端升级候选与正式数据库分开验证，不能把候选验收写成正式服务已升级。验证日志、资源回执及截图保存在本地任务目录，不进入公开资源。

## 资源反馈与投稿者署名

云端耗材与 LUT 的详情提供“反馈”，点击后打开“资源反馈”并读取投稿者署名。未登录也可查看署名；公开编号区分同名账号，保留同一账号更换邮箱后的身份。它表示投稿账号，不替代来源声明，也不认证原创。匿名署名及无法关联旧账号的数据不强行猜测作者。

资源问题统一反馈给维护者，由维护者处理并回复。没有普通用户直接联系投稿者的按钮、公开联系方式或对应填写设置。公开投稿者接口只提供编号与署名，Studio 对旧服务返回的联系字段也会过滤。旧数据库表保留升级兼容，不再提供联系资料的查询、编辑或公开接口。

已验证邮箱的社区账号可以反馈来源／署名、校准资料或链接问题。反馈绑定完整资源、修订及内容校验；需要至少十字说明。“补充资料（选填）”默认折叠，可附 HTTPS 链接及最多三张截图，支持文件选择、粘贴和拖入。只写文字也可提交。服务器核对公开版本、当前账号与 CSRF，重复请求沿用同一回执；同人同版本只能有一条待处理反馈，每账号每日最多十条、全站每日最多二百条，限制持久化。不同来源中同名但校验不符的资源不能混入主站记录。

正文、证据和维护者回复仅本人及维护者可见。“我的投稿 → 我的反馈记录”按需加载、分页读取；资源下架后仍可查回执，切换账号立即隔离私人内容。维护者使用 Registry 的 `scripts.manage_resource_reports` 留痕处理，修订与下架仍走原发布治理，举报不会自动删除内容。私人反馈、账号邮箱和联系资料表不进入公开数据导出。

截图在本机缩到最长边 1600px、单张不超过 1MiB 后上传，服务端独立检查实际格式、字节数和像素数，再重新编码为 JPEG 去掉原始元数据。反馈记录只带图片编号、尺寸和体积，展开时才通过当前账号读取内容。Registry v19 将图片保存在私人账号数据库，单账号图片预算 20MiB、服务总预算 256MiB；空间不足时仍可提交纯文字，不自动丢掉用户选择的截图。维护者可用 `scripts.manage_resource_reports ... image --report-id ... --image-id ... --output screenshot.jpg` 导出检查，要求现有管理员身份且不覆盖已有文件。旧服务可继续接收不含截图的反馈，截图功能要求升级到 v19。
