# 公开数据与官方云服务

2026-11-16：修订“两版默认使用同一个公共服务”的旧方案。数据公开、社区身份、官方托管服务分开处理。

## 两种默认路径

| 使用方式 | 自部署／源码运行 | 官方打包版 |
| --- | --- | --- |
| 默认目录 | 自动连接 GitHub 静态目录快照，无需填写地址 | 自动连接官方托管目录 |
| 内容 | 所有允许公开且已发布的耗材与 LUT | 同一资源身份的实时发布内容 |
| 找资源 | 轻量索引、本地搜索、组合筛选 | 托管目录及服务端检索 |
| 预览与下载 | 可见 LUT 按需加载预览，点击才下载该资源包 | 预览后按需下载，使用官方线路 |
| 点赞／收藏／下载人数 | 匿名读取公开统计快照，保留快照时间 | 匿名读取社区实时统计 |
| 个人点赞、收藏、投稿 | 现有社区账号 | 同一社区账号 |
| 离线资源 | 可下载公开离线包或导入文件 | 发行流程配套固定版本资源包 |
| 目录更新 | 应用自动检查公开快照；已安装资源按用户选择更新 | 应用检查官方目录；已安装资源按用户选择更新 |
| 软件运行与维护 | 用户负责源码运行环境和应用升级；无需部署耗材服务器或维护镜像 | 官方维护运行环境、应用更新、线路及配套资源 |

两版均可本地校准、转换和使用已有数据。不削减预览、搜索和单项下载，不在启动时安装全库。源码用户不需要 GitHub 账号，不需要为投稿提交 PR；投稿继续由 Registry 校验审核，维护者负责发布公开快照。

“自部署”仅指自行运行应用。默认资源目录由应用接好，启动后可直接搜索、预览、按项下载；自定义静态镜像或自建 Registry 是可选的高级配置。GitHub 是默认资源来源，社区身份仍由同一个 Registry 提供。

赞助优势来自官方持续提供的服务：实时目录、国内下载线路、配套离线包和运行维护。公共数据不划出仅付费可用的子集，作者署名和社区互动不拆成第二套账号。

## 当前状态

- “来源设置”支持恢复发行默认、主动切换 GitHub 或自定义同格式静态镜像，耗材和 LUT 共用偏好，保留搜索筛选、本地安装和社区账号；不会让源码首次启动依赖用户配置。
- Studio 源码默认读取 `Lumina-materials/master/public/v1`。`LUMINA_PUBLIC_CATALOG_URL` 可配置同格式静态镜像；明确配置 Registry 地址时继续使用实时协议。
- 发行层现有 `official-runtime.cjs` 显式设置官方 Registry 地址，源码默认源改变不会把打包版切到 GitHub。
- 首份 GitHub 公开快照及完整固定离线资源 2026.11.18.1 已发布：662 份耗材、99 个 LUT，包括六朔厂商供稿。匿名读取目录和所选单项包已验证。Registry 导出与发布器保留原公开署名、身份和原包，不导出数据库、邮箱、个人收藏、待审核或 team 数据。
- 数据仓库另有 GitHub Actions 每小时匿名拉取的同步工作流，无需在服务器存放 GitHub 写入密钥。复用未改变的包与色板，失败不替换快照；已用真实升级候选验证 761 个包全部复用，资源包网络下载为零。正式服务升级后才开启 `PUBLIC_CATALOG_SYNC=enabled`；当前定时同步保持关闭。
- 统计附带生成时间。未知或无法获取时显示 `—`，真实零值显示 `0`；GitHub 匿名下载不冒充账号下载人数。操作和图像转换中的收藏沿用社区账号及原资源 ID。
- **官方云权益校验尚未接通。** 当前官方公开读接口仍可匿名访问。默认地址分流区分了使用路径，但不是商业权限隔离。
- 候选服务端保留已配置的邮箱／GitHub 正常注册，注册开关默认开启，仅供运维显式暂停新注册；尚未部署。升级保留账号原有投稿和角色。
- 发行层已有官方地址注入；两类资源的离线包装配仍须由 Distribution 适配和验收，当前尚未发布对应安装包。

## 官方服务权益接入边界

启动器的激活服务应依据有效权益签发限定给耗材服务使用、可过期／撤销的访问凭据，由 Registry 服务端验证。不要复用管理 token，不把 `isPackaged`、环境变量、隐藏按钮或包内共享密码当成权限校验。

社区账号负责“谁在投稿、点赞、收藏”，服务凭据负责“谁有官方托管服务权益”。使用源码但持有有效服务权益的人也应能接入官方云。这样权益跟随用户，而不是某个二进制文件。

需要一起衔接启动器、激活后端、Registry 与镜像网关，再开启正式服务限制；不能只关一处公开读入口。离线包、已安装数据和公共快照继续可用。本节是接入边界，尚未修改正式权限、购买规则或现有用户权益。

## 静态发布与带宽

在 Registry 仓库执行：

```sh
python -m scripts.export_public_catalog \
  --data-dir /path/to/registry-data \
  --output /path/to/Lumina-materials/public/v1
```

输出目录：

```text
public/v1/
  materials/catalog.json
  materials/activity.json
  packages/<package-sha256>.zip
  luts/catalog.json
  luts/activity.json
  luts/previews/<preview-sha256>.json
  luts/packages/<package-sha256>.zip
```

包字节不变，文件名按包校验值固定；目录保留资源 ID、修订号、内容校验和原公开资料。同名不可变文件必须逐字节一致。所有包及预览验证完成后才替换目录。

上面的导出命令只写本地文件。Registry 另有 `python -m scripts.publish_public_catalog`，默认预演，只有明确加 `--publish` 才会推送；以独立索引生成一次提交，保留维护者工作区、暂存区及目录之外的文件。部署侧提供现有数据 Git 仓库、远端分支、独立状态目录与发布机器人身份，不用为每个普通投稿创建 PR。

Registry 附带的五分钟 systemd 推送模板仍可用于允许部署密钥的自建环境。组织数据仓库禁用部署密钥，因此正式同步采用数据仓库的 GitHub Actions 匿名拉取路径，服务器只承担已有公开读请求。工作流先跑校验，再读取完整目录、公开统计及需要的新包，成功后统一提交；没有内容变化不创建提交。正式服务器升级并验收后才开启小时调度。远端被他人更新时普通推送会拒绝，下一轮重新读取，不强推。

下架或转私有的资源及无引用包／预览从最新静态树移除，纠错沿用资源身份和新修订；不抹去 Git 历史、既有本地文件或固定离线包。无变化时不新增提交，也不刷新快照生成时间。正式启用后传播时间包括一次服务端调度、客户端五分钟缓存与静态托管缓存，不能承诺即时。完整部署和失败处理说明见 Registry 的 `docs/public-catalog-publishing.md`。

客户端不遍历 GitHub API，不在搜索时请求服务器，不下载整库 ZIP。目录与统计本地缓存五分钟，手动刷新目录会重新验证；静态镜像支持 ETag 时可返回 304。LUT 预览按可见条目读取并校验，单独缓存，避免挤掉索引。下载沿用现有包校验、更新识别和历史恢复；失败不自动切回官方云。

静态请求匿名且禁止重定向，包路径限定在选定目录内，不放宽 Registry 同源约束。单个导出包当前上限 32 MiB，超限明确终止，不悄悄遗漏资源；更大资源需另行设计分发方式。

## 上线顺序

1. 验收本地真实服务与静态目录两条路径。
2. 复核公开范围，发布首份 `public/v1`；发布前不能把新的 GitHub 默认源先发给普通用户。
3. 恢复并验证完整离线包装配改动，再发布新版应用。
4. 完成启动器到 Registry 的权益联动及网关策略，验证有效、过期、撤销和离线情况，再启用正式服务限制。

已发布公开数据与固定资源包，并将用户确认的六朔厂商供稿接入原正式数据服务。主程序与 Registry 代码仍按 PR 审核；正式 Registry 程序未切换到升级候选，未构建或发布新的软件安装包。
