# 耗材档案与 LUT：资料规则和上传模板

资源资料分为“一卷耗材”和“一组 LUT 配色”两类。共用品牌、地区包装名、色号和商品链接规则，表单分别适配；上传者不需要在文件名里编码这些信息。

本次已接入列表／详情展示、搜索、资料传递和主动投稿入口。账号沿用耗材服务器的登录与投稿身份，通过网页确认会话或长期设备连接。实际入口、配置及本次边界见[资源投稿](resource-contributions.md)。表单支持可选中国区／国际商品名、最多八条地区购买链接；系列优先提供本机已有资料和已维护产品表中的候选值，同时允许新填。

## 展示规则

| 信息 | 列表 | 详情 |
| --- | --- | --- |
| 名称 | 简洁资源名，不拼日期、作者和文件后缀 | 同名标题，原始名称另列 |
| 品牌 | 固定品牌行，标志最大 72×32px，按原比例缩放＋地区名称 | 标志最大 96×40px；LUT 可逐通道列不同品牌，槽位行沿用列表尺寸 |
| 材质／系列 | 显示已有材质；系列能帮助选料时进入名称 | 完整系列、材质、颜色名、包装色号 |
| 使用颜色 | LUT 显示记录的色名与小色点；仅有 RGB 时显示色点 | 通道名称／编号及实际耗材，保持文件顺序 |
| 校准 | 显示公开点赞、收藏与下载人数，颜色模式按需保留；拟合误差进入详情 | 层高、验证记录和来源条件 |
| 作者、原名、说明 | 作者与原名可搜索，不重复堆在列表 | 按独立字段展示 |
| 商品链接 | 不出现 | 有效链接、渠道标签和目标域名；按地区筛选 |

Logo 只由维护的品牌表决定，用户填写名称不能获得“官方”或“赞助”身份。横向字标允许使用更宽的空间，方形与竖向图案按高度控制，保持比例，不裁切或拉伸；筛选菜单使用 64×28px 对齐槽位，详见 [品牌标志尺寸](../DESIGN.md#品牌标志尺寸)。标志使用透明展示区，按应用主题选用预制的明暗素材：单色字标调整深浅，多色标志保留配色关系，过暗色墨使用同色系亮版。原图的矩形底色在素材维护时去除，不在运行时抠图或整图反色；原始来源保留。无标志就只显示品牌名，不以相似品牌代替。混合品牌 LUT 不选一个品牌的 Logo 代表整组。

旧数据兼容规则：完整品牌别名可归一；规范的 `品牌&材质&颜色模式&配色&日期` 文件名可以投影为简洁名称，原名保留。作者自定义标题不按模糊关键词截断。搜索始终覆盖原名、地区名称、品牌别名与色号。颜色模式不能确定具体耗材产品；校准板的配方像素也不是原料色。没有具体配色记录时，详情明确显示缺失。

包装名称按设置中的地区统一选择，默认跟随界面语言。已有地区名称优先；规范标题省略材质时，用记录的材质、系列、颜色完整匹配维护的品牌色表，列表与详情使用相同的地区色名。通用色名可使用维护的描述翻译，不生成商品色号；未收录的特殊商品名保留原文。Basic、Matte 等系列名保留商品原文。作者自定义标题、冲突色号及原始名称不会被这条兼容规则改写。

旧文件名中的编号保留为来源线索，不在前端仅凭编号补系列或覆盖自定义标题。补齐产品身份须结合原档案、厂家资料和人工核对，并写入目录元数据。购买入口须区分已核实的商品与品牌店铺；单一品牌的 LUT 可以提供品牌店铺入口，这不表示已确认每个通道的具体耗材。

详情里的原始名称优先显示资料保留的 `display.original_name`，缺失时再使用传入的旧名称；规范后的标题不覆盖原文件名里的色号、作者和采集说明。

具体槽位资料优先于旧文件名。完整有效的 `slot` 编号按通道顺序展示；旧文件名只在配色字段完整、数量与已知模式相符时提供颜色摘要，不从半截名称拼配色。通用色名的小色点是识别提示，精确产品以品牌、系列和色号为准；有记录的 RGB 优先使用记录值。

## 耗材档案模板

上传流程为：选择档案 → 自动读取校准信息 → 确认这卷料 → 预览展示 → 提交。

| 字段 | 填写方式 | 规则 |
| --- | --- | --- |
| 品牌 | 可搜索下拉，允许“品牌不在列表中” | 保存品牌标识及原始输入；不要求用户上传 Logo |
| 材质 | 下拉选择；特殊材质可补充 | 与已读取的档案类型冲突时提示确认 |
| 系列 | 同品牌已有系列可选，也可新填 | 如 PLA Basic、PETG HF；不能仅从代表色猜 |
| 颜色名称 | 按包装填写 | 不是通用颜色分类；特殊商品名保持原文 |
| 包装色号／货号 | 文本，选填 | 保留前导零与大小写；跨地区同色号可关联 |
| 包装地区 | 中国大陆／国际／两者 | 名称按地区记录；不强制要求英文译名 |
| 显示名称 | 从系列＋颜色名建议生成，可编辑 | 不拼作者、日期、路径 |
| 商品链接 | 地区、渠道名称、URL，可添加多条 | 选填；只接受 http/https，不含账号密码；原样保留合法参数 |
| 耗材说明 | 简短文本，选填 | 特殊效果、批次等；不放内部日志 |
| 层高、采样与拟合 | 从文件读取，默认只读 | 本轮不替用户改校准数据 |
| 署名／公开许可 | 使用服务器投稿流程确认 | 投稿者身份来自会话；历史作者署名单独保留 |

同一商品可以有多份不同作者、批次或层高的档案。商品身份和测量档案身份分开，不能按简洁名称直接合并数据。

可填样本：[material-profile.json](templates/resources/material-profile.json)。`null` 表示待填或未提供；模板样本不包含虚构商品页。

## LUT 模板

上传流程为：选择 LUT → 读取模式与通道 → 按槽位确认耗材 → 补充名称与说明 → 预览展示 → 提交。

| 字段 | 填写方式 | 规则 |
| --- | --- | --- |
| LUT 名称 | 建议“材质 · 配色”，可编辑 | 不要求统一成文件名；保留创作者自定义名称 |
| 模式、通道数 | 解析文件，默认只读 | 与配方、槽位共同校验，不凭标题覆盖文件 |
| 每个槽位的耗材 | 优先选择已有耗材档案；也可手动填商品信息 | 选择档案后自动带出品牌、系列、色号和链接 |
| 槽位顺序 | 按文件展示为 1、2、3… | 存储 `slot` 从 0 开始；不按色名、品牌或白底自动重排 |
| 具体耗材缺失 | 标记待补充 | 旧 LUT 可照常使用；发布新投稿前指出缺失槽位，不能自动猜料 |
| 品牌 | 从已确认槽位汇总 | 全部同品牌显示该品牌；多个品牌显示“混合品牌”；部分未知保留未知状态 |
| 商品链接 | 跟随每个槽位的耗材 | 不默认让整组 LUT 共用一个购买链接；已有整组商品链接可另列 |
| 层高、层数、基底、配方 | 从文件读取 | 允许核对，不通过填写资料改算法或配方 |
| 署名、说明、许可 | 复用服务器投稿机制 | 作者与投稿者分开；邮箱不公开进入资源资料 |

五色基础／扩展板和八色 A／B 板是一套 LUT 的预览页面，共用同一份槽位清单，不要求重复填写两份耗材。合并或自定义 LUT 保留其真实通道，不套用固定四色／八色默认配色。

可填样本：[lut.json](templates/resources/lut.json)。`filaments` 的长度及 `slot` 集合必须与解析后的 LUT 通道一致；已有档案关联必须同时保存资源 ID 和修订 ID，防止远端更新悄悄改变作者当时使用的耗材。

## 数据衔接

展示字段放入现有包／目录的 `display`，避免新增一套并行资源数据库。新增字段为 `series`、`description`、`purchase_links`、`product_url`／`purchase_url` 兼容入口，以及 LUT 的 `filaments`。地区包装沿用 `market_names`，色号沿用 `color_code`／`sku`，原始名称和资源 ID 保持不变。

`purchase_links` 项使用 `market`（`CN`／`INTL`／`ALL`）、`label` 和 `url`。显示链接不代表软件认证店铺；只有已维护的证据才能标为官方。服务器投稿校验需要复用同一限制，浏览器侧过滤只负责展示。当前没有给缺链接的旧资源生成搜索网址。

表单提交前展示与目录一致的预览卡片和详情，让用户看到最终效果。品牌字典、常用系列与材质由下拉提供；文件可自动读出的字段不重复手填。公开目录、GitHub 数据快照与离线包保留同一组字段，安装到本地后显示身份不改变。

## 检索字段

关键词覆盖原名、地区包装名、品牌别名、材质、系列、颜色名、包装色号和公开署名。多个词同时满足；全角字符归一，中文与英文连写可以拆开，完整色号优先于标题中的提及。不对色号做模糊纠错，避免把相近编号当作同一卷料。服务器返回的拼音／别名同时进入 Studio 索引。

耗材可按品牌、材质、系列和色系筛选。LUT 额外按色数筛选，其品牌、材质、系列和颜色来自已声明的槽位；混合品牌可被其中任一品牌找到。LUT 选择多个色系表示同时包含这些原料颜色。五色／八色的双校准板仍算一个条目。

色系是粗粒度浏览提示，优先用记录的色名，缺少通用色名时用记录的 RGB 分组；不改变原包装名或测量数据。未记录的系列／原料颜色不参与对应筛选，文件中真实保存的通道 RGB 可以参与。旧 LUT 的规范完整配色字段按既有规则兼容，不读取校准板配方像素来补原料资料。

上传表单保存这些结构化字段后直接进入检索；不让用户另外维护“搜索关键词”。账号 ID、邮箱、审核记录、购买链接参数和预览二进制均不作为关键词。传输、缓存与扩展路线见 [资源检索与服务器衔接](resource-search.md)。
